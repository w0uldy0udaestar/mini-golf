# T5 「내 모니터에서 열린 메이저」: 계획 · 비트 시트 · 결정 근거 · 숫자 출처

> 2026-10-06 (2차 수정 반영) · 스레드 세로 1080×1920 · 30fps × 360프레임 = 12.0초 · HyperFrames 0.8.70 + GSAP 3.14.2 · Pretendard 로컬 번들
> 산출: `dist/ads/threads/t5-broadcast-v-ko.mp4` · 시트 `t5-broadcast-sheet.png` · QA `t5-broadcast-qa.md` (+ 측정값 `t5-broadcast-qa.json`)

## 한 줄
TV 골프 중계 그래픽(생중계 태그, 홀 버그, 리더보드, 샷 트레이서, 스탯 판, 해설 자막)을 진지하게 쓰되, 화면에 나오는 건 내 바탕화면의 코드 창과 맨 아래 띠의 스틱맨이다. 실제 게임 드라이브 한 샷이 코드 창 위로 272m를 날아가고, 로그대로 벙커에 선다. 중계는 끝까지 진지하다.

## 구조
- 셸 `vertical.html` 하나. 그림은 전부 `src/main.js`가 그리고, 모든 상태는 `render(t)`가 t만 보고 계산한다. Math.random·Date·네트워크는 쓰지 않는다.
- 소재 준비는 `scripts/prep.py`가 맡는다. 판과 스윙 크롭은 15초 광고와 같은 규칙으로 `dist/cap/ad`에서 다시 만든다. 탄도 `data/shot.js`는 Ballistics 이식과 실캡처 맞춤으로 만든다. 게임은 다시 실행하지 않았다.
- `data/rig.js`·`data/ground.js`는 15초 광고의 실제 리그 덤프와 지형 프로파일을 복사했다(임팩트 f11 정렬 동일).
- 오디오 `scripts/make-audio.py`는 numpy 합성이고 외부 음원은 없다.
- 렌더 `scripts/render.sh`는 두 단계다. HyperFrames PNG 시퀀스(워커 1, 소프트웨어 래스터) → ffmpeg/x264 고정 설정 + AAC. QA는 `scripts/qa.py`, 시트는 `scripts/sheet.py`.

## 숫자·사실 출처 (지어낸 것 없음)
원본 로그는 `dist/cap/ad/logs/hero-drive.log`(15초 광고의 실캡처 세션)다. 계산은 `scripts/prep.py`이고, 실행할 때 근거를 출력한다.

| 자막 | 값 | 출처 | 계산 |
|---|---|---|---|
| 홀 버그 | 3번 홀 · 파 5 · 578 m | `PLAY HOLE 3 par 5 skyTee tee 54 cup 632` | 632 − 54 = 578. 게임 HUD "티 · 578m"와 같다 |
| 버그 아래 줄 | 절벽 티 · 바람 → 1 m/s | 판(`terrain-skytee`)의 게임 HUD 글자 | 그대로 옮김 |
| 리더보드 | 1 나 E | HUD "합계 E" | 그대로 둔다. 순위 칸 반전은 강조 연출일 뿐 값 변화가 아니다 |
| 볼 스피드 | **67 m/s** | `ClubTable` DR power 69 · `Ballistics.launch` · `GameScene.launchBall` | v0 = 69 × 1.0 × (0.25 + 0.75 × h1.00) × (1 − 0.12·\|m\|). h1.00 풀파워의 미스힛 m은 로그에 없다. 그래서 `Ballistics.step(.fly)` 이식으로 실캡처 궤적(정점 높이·위치, 착지 표고차)에 맞춰 역산했다. m = +0.27 → 66.76 m/s(근접 해 11개 66.35–67.10) → 67 |
| 정점 | **27 m** (티 기준) | 이식 탄도 / 실캡처 궤적 | 27.2 m / 108.5 pt ÷ (2.8358 pt/m × 1.4) = 27.3 m |
| 캐리 | **272 m** | `LANDCUE check x 326` · `PLAY SHOT 1 DR h1.00 from 54.2 lie tee` | 326 − 54.2 = 271.8 → 272 (±0.5 m) |
| 라이 | **벙커** | `PLAY REST strokes 1 x 342.0 lie bunker` | 로그 필드 그대로. 공의 정지 위치도 342.0 m 그대로 |
| (화면 시간) | 물리 시간 ÷ 2.512 | 실캡처 공 표본 3개 | 2.516 · 2.486 · 2.533 |

"토탈 288 m"(342.0 − 54.2)는 1차판에 있었으나 2차에서 "라이 [벙커]"로 바꿨다.

## 결정 근거
1. **벙커를 숨기지 않고 웃음으로 썼다(2차).** 로그가 `lie bunker`이므로 착지와 정지를 중계 문법으로 그대로 보여 준다. 스탯 판에 흰 태그 **벙커**를 띄우고, 해설은 "이 샷, 코드 창 위를 넘어갑니다." → "…벙커입니다."로 이어진다. 리더보드는 그대로 두고 순위 칸만 한 번 반전한다. 톤은 끝까지 진지하게 유지한다. "−1"이나 "온그린"은 이 샷의 사실이 아니라서 쓰지 않았다.
2. **중반을 압축했다(2차).** 14초에서 12초로 줄였다. 정지(4.8초) → 벙커 해설(5.0–6.5) → 태그라인(6.5–8.5) → 엔드(8.5–12) 순서다. 1차판은 정지 뒤 9초가 정지된 궤적 그림이었다.
3. **훅 보강(2차).** 임팩트 섬광은 정점 1프레임에 2프레임 꼬리를 붙였다. 딱 1프레임만 켰다 끄면 글리치처럼 보이기 때문이다. 섬광 면적이 작아 플래시 검사는 0회다. 볼 스피드 줄은 임팩트와 함께 뜬다.
4. 홀 정보는 브리프 예시("1번 홀 · 파 4 · 386m") 대신 캡처한 홀의 실제 값을 썼다.
5. **화면 구성**: 데스크탑 아래 가장자리를 y 1490에 고정하고, 그 아래는 중계 자막 띠로 쓴다. 16:9 데스크탑을 꽉 채우면 띠와 착지점이 스레드 UI 영역(아래 300px)으로 내려가기 때문이다.
6. **카메라**는 2D scale/translate만 쓴다. ×2.4 훅 → 풀백 ×1.4 → 공을 따라 패닝(단조 에르미트, 속도 연속) → 느린 푸시 ×1.045 순서다. 회전·원근·흔들림은 없다.
7. **트레이서**는 흰색 3겹이고 non-scaling-stroke이며 착지점에서 멈춘다. 빨강은 쓰지 않았다.
8. **빨강**: 생중계 점 하나. 그 밖에 캡처 그대로인 스틱맨 왕관과 메뉴바 깃발 아이콘에도 빨강이 있다(코디네이터 지시로 유지).
9. **결정적 렌더(2차 실측)**
   - HyperFrames mp4 직출력은 실행마다 첫 GOP(250f)가 달랐다.
   - 원인을 나눠 보니, 기본 GPU 래스터에서 5회 중 1회가 풀백 중(f29–31) 판 이미지 영역에서 1~2레벨 달랐다. x264는 같은 PNG면 같은 파일을 냈다.
   - 그래서 `--no-browser-gpu`(소프트웨어 래스터) PNG 시퀀스 → ffmpeg/x264 고정 설정으로 바꿨다.
   - 그 뒤 PNG 시퀀스 4회와 최종 mp4 2회가 바이트까지 동일했다.
   - GPU판과의 화면 차이는 평균 0.2–0.4레벨(안티에일리어싱)이다.
10. **소리**는 없어도 완결된다. 켜면 야외 공기, 패드, 우시, 드라이버 타격음, 착지 탭, 차임이 들린다(SoundKit 레시피 이식). 통합 −16.0 LUFS, TP −3.9 dBFS.

## 실캡처 vs 코드 근사

| 요소 | 출처 |
|---|---|
| 지형선·러프 틱·게임 HUD | **실캡처** `terrain-skytee` |
| 훅 스윙 톱·다운·임팩트·팔로·피니시 (f0–20) | **실캡처** 크롭 5장 |
| 스윙 뒤 스틱맨(트레이드마크 동작, 엔드에서 걷기) | **실제 리그 덤프**(60Hz) → StickmanNode 렌더 규칙 |
| 공 비행 경로·시간 | **게임 물리 이식** + 실캡처에 맞춘 미스힛 해, 화면 시간은 실캡처 표본 배율 |
| 착지 뒤 튐·굴림 → 벙커 정지 | 실캡처 f184 표본과 REST 위치(342.0 m)·시각을 지나는 근사 |
| 임팩트 섬광 | 코드(방사형 그라디언트, 3프레임) |
| 데스크탑·코드 창·터미널·메뉴바·중계 그래픽 | HTML/CSS 일반형(실제 방송사·대회 로고·서체 없음) |
| 효과음 | SoundKit 레시피 이식, 바닥·패드는 신규 합성 |
