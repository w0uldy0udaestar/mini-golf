# 스틱맨 리그 개편 리서치 — 관절·걷기 속도·전환 (2026-09-14)

사용자 피드백 5건(전환 끊김·걷기 가속·고무팔·모션 획일·서프라이즈) 중 **1·2·3번**을 구현하기
전에 "남이 이미 풀어둔 것"을 조사한 결과와, 그 위에 세운 설계안. 원자료 보고서 2건은
`research-stickman-rig-raw-impl.md`(구현체·에셋), `research-stickman-rig-raw-techniques.md`(기법·문헌).

## 결론

1. **그대로 가져올 Swift/SpriteKit 2D 절차 스틱맨 리그는 없다.** 직접 구현이 전제. 대신 문제별로
   검증된 알고리즘·수치를 가져온다.
2. **관절(3번)**: Ryan Juckett의 2D 2-bone IK 해석해(zlib형 퍼미시브)를 60줄 안팎으로 이식.
   사이드뷰라 pole 벡터 대신 굽힘 부호 상수 하나면 된다. SpriteKit 내장 IK(`SKReachConstraints`,
   `SKAction.reach`)는 실존하지만 노드 트리·시간 액션 기반이라 점 좌표 리그와 맞지 않아 **기각**.
3. **걷기 속도(2번)**: 전 구간 포물선을 버리고 **앞으로 몰린 가속 램프(약 2걸음) → 등속 → 짧은
   감속(예고 0.15초 + 2~3걸음)** 프로파일로. 보폭·케이던스는 √v 비례(walk ratio 상수의 귀결) —
   현재 게이트의 `stepL ∝ √v`는 이미 맞다.
4. **전환(1번)**: 8-14의 실패는 튜닝이 아니라 구조 문제. 접지 발은 월드 고정 제약인데 포즈 평균은
   제3의 점을 만들어 반드시 미끄러진다. 답은 **원점 통일 + 거리 구동 위상(이미 있음) + 마지막
   2걸음 발자국 계획 + 상체만 inertialization**.
5. 4번(모션 다양성)을 위한 데이터 후보는 확보됐다: Quaternius Universal Animation Library(CC0,
   120+종)와 보행 생체역학 데이터셋(CC BY 4.0). 이번 단계에서는 쓰지 않는다.

## 설계안 (1·2·3번)

### 3번 관절 뼈대 — "점 리그 유지 + 관절 제약 후처리" (권장)

기존 `Rig`(점 좌표)는 그대로 두고, 렌더 직전에 `Skeleton.solve(rig)`가 뼈 길이를 강제한다.
스윙 P-System·걷기 빌더·의식·100종 모션 코드가 전부 그대로 동작하고, 손·발 목표점만 "닿는
범위"로 클램프된다. 대안인 전면 각도 기반 재작성은 4번(모션 재설계) 때 필요한 만큼만 한다.

- 뼈 길이(현 리그에서 유도): 몸통 24.5 · 위팔 17 + 아래팔 17 = 34(어드레스 handD 34가 완전 신전)
  · 허벅지 22.5 + 정강이 22.5 = 45(직립 44.4). 실측 가동범위 참고: 무릎 유각기 60~70°.
- 다리: 힙→발 거리가 45를 넘으면 힙 높이를 내려 맞춘다(도립 진자 — 접지 순간 최저). **발 위치는
  절대 건드리지 않는다**(노슬립 불변). 무릎은 IK 해, 굽힘 부호 = 바라보는 쪽(+facing).
- 팔: 어깨→손 거리가 34를 넘으면 손을 `min(d, 0.985·34)`로 당기고 소프트닝. 팔꿈치 굽힘 부호 =
  −facing(뒤). 클럽 그립은 스윙 중 handD 28~34라 항상 범위 안 → 스윙 궤적 불변.
- 도달 불가의 보상은 동작 쪽에서: 공 줍기·티 꽂기 의식은 손이 컵에 닿도록 허리 힌지·무릎 굴곡을
  더 주도록 키포즈를 재조정(모캡 비율은 유지).
- 렌더: 다리·팔을 `hip→knee→foot`, `shoulder→elbow→hand` 꺾인 선(round join)으로. 척추 곡선은 유지.

### 2번 걷기 속도 — 사다리꼴 프로파일

- 위치 곡선 `smoothstep(u)`를 **램프-등속-램프**로 교체. 램프 시간은 거리와 무관하게 고정:
  가속 0.9초(앞으로 몰린 형태: `1−exp` 또는 smoothstep 램프), 감속 1.1초(예고 0.15초 포함),
  각각 `dur/3` 상한. 등속 `vc = dist / (dur − (tIn+tOut)/2)`. 위치는 램프 적분의 닫힌식으로,
  `vInst`는 그 도함수 — **위치·속도 한 쌍 유지**(HANDOFF 원칙).
- 게이트의 `stepL ∝ √v`, `duty` 속도 의존은 유지. 램프 극초반 보폭 하한(0.5) 유지.
- 몸 바운스 진폭은 속도 연동 유지(실측 2.7→4.8cm 비율과 방향 일치).

### 1번 전환 — 원점 통일 + 발자국 계획 + 상체 inertialization

1. **원점 통일**: 걷기의 목표를 공이 아니라 **몸이 설 자리**(`ball.x − dir·ballFwd/pxPerM`)로.
   출발도 어드레스 몸 위치에서. 도착 순간 `stickX = ball.x`로 바꾸되 포즈의 `−ballFwd` 오프셋이
   상쇄해 월드 좌표 점프 0. (8-14의 "원점 블렌드"와 다름 — 블렌드가 아니라 좌표계 정의를 맞춘다.)
2. **출발 발 위치**: 게이트 초기 접지점을 어드레스 스탠스(−16, +11)로. 뒷발이 먼저 짧게 나간다
   (실제 gait initiation 패턴).
3. **도착 발자국 계획**: 정지 몸 위치는 프로파일에서 확정적이므로, 잔여 거리가 2걸음 이내면 각 발의
   `swingTo`를 스탠스 목표(정지 위치 −16 / +11)로 대체. 보폭 변화 ±30% 이내면 즉시, 넘으면 한
   걸음 더 쓴다. 마지막 스윙 발은 위상이 아니라 잔여 거리 비율로 진행시켜 v=0에서 정확히 착지.
4. **상체·팔·머리 inertialization**: 모드 전환 시 각 채널의 오프셋·변화율을 기록하고 Holden
   cubic으로 0.25~0.35초에 감쇠. 접지 발·무릎에는 적용하지 않는다. 지수 추적(`chase`)은 스윙
   다운스윙 잠금 등 기존 예외를 유지하고, 전환 구간만 대체.
5. **예고·여운**: 정지 0.15초 전 상체 무게중심 소폭 전방, 마지막 착지 후 상체 오버슛→정착
   (halflife 0.12~0.2초), 어드레스 진입 시 골반 2~3px 하강 + 무릎 굴곡.
6. 방향 반전(공이 뒤에 있을 때)의 한 프레임 미러는 이번 범위 밖 — IDEAS에 기록.

## 한계와 공백

- 60fps 2D 스틱맨 전용 사례 연구는 없다. 위 기법은 3D·클립 기반에서 검증된 것의 번역이며 번역
  자체는 미검증. 보폭 조정 한계 ±30%는 실측이 아닌 제안값.
- 보행 개시 "1~2걸음" 근거(Brenière & Do 1986, 2025 논문)는 원문 미확보·단일 경로.
- Crenna 2001의 "계획된 정지는 발목 주도"라는 에이전트 표현은 부정확 — 원문은 원위→근위 순차
  활성이며 속도가 높을수록 고관절·대퇴 의존이 커진다. 설계에는 영향 없음.
- 골프 게임의 걷기→어드레스 전환 공개 자료는 찾지 못했다. Alan Becker 류 스틱맨 실무 원칙은 영상
  존재만 확인, 텍스트 검증 실패.
- Mixamo 유지보수 상태는 2차 출처 1개뿐. 사용 계획 없음.
- 8-14 실험실의 "다운스윙 스프링 불가" 결론은 유지: 다운스윙은 리그=타깃 잠금.
